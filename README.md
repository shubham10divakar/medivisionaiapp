# MediVision AI — Android app

An Expo / React Native companion to **[medivisionai.in](https://medivisionai.in)**:
capture or pick a chest X-ray, run it through the open **NIH ChestX-ray14** models
that power the website, see all 14 thoracic findings scored with confidence, and
read a plain-language reference for each one.

> ⚠️ **Research and educational demo. Not a medical device.** Not for diagnosis,
> triage, or any clinical decision.

Built on the same structure as the PlantDoc app, retargeted from single-label
plant disease → **multilabel chest X-ray**.

## Stack

| Layer | Choice |
|---|---|
| Framework | React Native 0.76 + Expo SDK 52 |
| Routing | expo-router (file-based) — 5 tabs + stack screens |
| State | zustand + AsyncStorage (`store/useStore.ts`) |
| Auth | Firebase Auth — Google, email/password, anonymous (`services/firebase.ts`) |
| Cloud history | Cloud Firestore (`users/{uid}/runs`) |
| Camera / images | expo-camera, expo-image-picker, expo-image-manipulator |
| Backend | `https://medivisionai.in/api` — `GET /models`, `POST /predict` |

The backend's nginx gateway injects the API key server-side, so **no secret ships
in the app**. Base URL is `EXPO_PUBLIC_API_URL` (`.env`) and is overridable in
Settings.

## The prediction flow

1. **Demo tab** — pick from camera or gallery. Image is downscaled to ≤1024 px
   JPEG (`utils/image.ts`) before upload.
2. Choose a model (list comes from `GET /models`, falls back to the two known
   models) and a **decision threshold** (default 0.5).
3. `POST /predict` with `file` + `model_name` + `threshold`.
4. **Result screen** — the image, a "N positive findings" badge, positive-finding
   chips, then all 14 ChestX-ray14 labels as animated confidence bars sorted by
   score. Tap any finding → its explainer in `condition.tsx`.
5. Saved to on-device history; if signed in, a **summary** (model, positive
   labels, latency, threshold — never the image) is written to Firestore.

First prediction after the model server has been idle can take ~20 s (cold
start); the loading overlay says so.

## Run it

Prereqs: Node 20+, Expo tooling, Android SDK + a device/emulator.

```bash
cd "MediVisionAI app/app"      # or wherever you cloned it
npm install
cp .env.example .env           # already points at https://medivisionai.in/api

# 1. Generate the native project (re-run after adding/removing Expo plugins or
#    native modules like Firebase):
npx expo prebuild --platform android --clean

# 2. Run a debug build:
npx expo run:android
```

`npm run typecheck` runs `tsc --noEmit`. Release APK/AAB: see `LOCAL_BUILD.md`.

**Without Firebase configured**, the app still runs: it drops to a local-only
"demo" user after ~5 s, on-device history works, cloud history and Google
sign-in are disabled. See `FIREBASE_SETUP.md` to enable them.

## What's done

**App**
- All 5 tabs + `result`, `condition`, `login`, `onboarding` screens, fully wired.
- API client with typed errors, human-readable messages for 409/413/415/429/502/504,
  and a `healthCheck` (pings `GET /models` since `/health` isn't exposed publicly).
- Live model picker (`GET /models`) with an offline fallback list.
- Decision-threshold control (−/+ nudge + 0.25 / 0.5 / 0.75 presets).
- Result screen: positive-finding chips, all-14 confidence bars, tap-through to
  explainers.
- `constants/conditions.ts`: written reference for all 14 findings (what it is,
  what a positive read suggests, common causes, radiographic signs) + a generic
  template so any future label still renders.
- On-device history (zustand + AsyncStorage), Home dashboard stats.
- Dark-first theme matching medivisionai.in, with a light variant and a dark-mode
  toggle.
- "Not a medical device" disclaimer on Home, Demo, Result, and every Learn detail.
- Onboarding carousel + one-time coach marks.
- Feedback modal (Firestore + mailto fallback).
- Settings: account, dark mode, editable + testable API URL, default model.
- **Local-demo fallback** so the app is usable with zero setup.
- Verified: `tsc --noEmit` clean · `expo export --platform android` bundles clean ·
  `expo-doctor` 18/18.

**Firebase (code only)**
- Google, email/password, and anonymous sign-in; sign-out; password reset.
- `users/{uid}/runs` cloud history (summary docs), `feedback` collection.
- Graceful degradation when the native module / `google-services.json` is absent.

**Docs**
- `README.md` (this file), `FIREBASE_SETUP.md`, `LOCAL_BUILD.md`.

## What's pending

**Blocking a real build / release**
1. **Create the Firebase project** — enable Email/Google/Anonymous auth + Firestore,
   register `com.medivisionai.app` with debug + release SHA-1s, add
   `google-services.json`, set `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, apply the
   Firestore rules. All steps in `FIREBASE_SETUP.md`.
2. **`npx expo prebuild --platform android`** to generate the native `android/`
   project (it's `.gitignore`d — regenerated per machine).
3. **Run it on a device/emulator** — nothing here has executed on-device yet;
   expect small layout tweaks.
4. **Release keystore** + signing config wired into `android/app/build.gradle`
   (`LOCAL_BUILD.md`).

**Polish before shipping**
- Replace the **placeholder app icon / splash** (`assets/images/icon.png`,
  `adaptive-icon.png`) with real artwork.
- Empty-state / error copy review on Demo and History.
- A sample X-ray bundled in the app so first-run users can try it without a file.
- Confirm `expo-image-picker`'s `MediaTypeOptions` (deprecated in SDK 52) vs the
  newer `mediaTypes: ['images']` — currently uses the old form for parity.

**Nice-to-have / later**
- iOS target (bundle id is reserved; needs `GoogleService-Info.plist` + an
  `expo prebuild --platform ios`).
- Surface the COVID models automatically once the backend marks them `ready`
  (the picker already would — just needs backend work; see the `spaces code` repo).
- Multiclass rendering path in `result.tsx` is written defensively but untested
  (no multiclass model is live).
- A debug-log viewer in Settings (store already collects `debugLogs`).
- Share / export a result as an image.
- Play Store listing assets + privacy policy (required — the app uses camera,
  photos, and an account system).
